# 《传奇》本地单机复刻 — 设计方案 v0.1

> 目标: 用 Unity 简易、快速地做一版能在本机玩的《热血传奇 / Mir2》风格游戏。
> 原则: **先跑通「打怪→爆装→回城卖→变强」这条核心循环**，其余全部往后放。

---

## 0. TL;DR（结论先行）

| 决策项 | 结论 |
| --- | --- |
| 定位 | 单机离线「传奇手感」垂直切片 → 可玩小世界，**不做网络** |
| 引擎 | Unity **6.3 LTS (6000.3.x)** + 2D (URP) 模板 |
| 视角 | 斜俯视 2.5D 网格世界，正交相机 + 按 Y 排序 |
| 移动 | **格子步进**（每 tick 最多 1 格），不是自由刚体 |
| 逻辑时钟 | **固定 10Hz tick**（100ms），表现层插值 |
| 逻辑/表现 | 逻辑层纯 C# 不依赖 UnityEngine，表现层只做「读 World + 播动画」 |
| 数据 | **JSON 表驱动**（怪物/物品/技能/地图/掉落），可热重载 |
| 美术 | 先用**程序化占位图**，统一 sprite 规格，后期换 CC0 素材；**不使用原版素材** |
| 目标周期 | MVP 约 **17~25 人日**；业余晚上做 ≈ 6~8 周 |

## 1. 目标与非目标

### 1.1 要复刻的「传奇味」（只保留这 5 条）

1. **斜俯视的格子世界** — 相机跟随、屏幕外全是怪、地图边界与传送点。
2. **一格一格的顿挫节奏** — 走路一步一格，攻击有挥砍动作和收招硬直，攻速/移速是数值。
3. **装备驱动的成长** — 打怪 → 爆装 → 捡取 → 回城卖钱 → 换装变强 → 去更硬的地图。
4. **背包格子** — 48 格，捡满了就捡不下。（原本还设计了负重上限，试玩后按需求**移除**了：见 §11。）
5. **直白的数值** — 破坏(DC)/魔法(MC)/道术(SC)/防御(AC)/魔御(MAC)/HP/MP 都写在装备上，一眼看得懂。

### 1.2 明确不做（Non-goals）

- ❌ 联机 / 服务端 / 账号 / 行会 / 沙巴克 / 交易
- ❌ 复刻原版 .wil .wix .map .tbl 二进制格式（改为自有 JSON + PNG）
- ❌ 复杂任务与剧情线、完整世界观
- ❌ 自研地图编辑器（前期直接用 Tiled 或手写 JSON）
- ❌ 移动端 / 手柄适配（先做 PC 键鼠）
- ❌ 原版美术、音效、名称、LOGO 的搬运（版权）

## 2. 技术选型（决策表）

| 维度 | 备选 | **推荐** | 理由 |
| --- | --- | --- | --- |
| Unity 版本 | 6.6 / 6.3 LTS / 6.0 LTS | **6000.6.1f1** | 本机已装并实测通过；工程用官方 Universal 2D 模板搭好，版本锁在 ProjectVersion.txt |
| 渲染管线 | Built-in / URP 2D | **URP 2D** | Unity 6 默认模板；以后加后处理、光照、描边不用重做 |
| 移动模型 | Rigidbody2D 自由移动 / 网格步进 | **网格步进** | 无物理抖动、碰撞确定性、A* 寻路天然适配、存档只需存格坐标 |
| 逻辑时钟 | Update 每帧 / 固定 tick | **固定 10Hz tick** | 复刻原版节奏；数值可调；逻辑与帧率解耦，快进/挂机好做 |
| 地图 | Unity Tilemap 全套 / Tilemap 只做渲染 | **Tilemap 渲 + 自维护通行表** | 渲染用 Unity 工具链，通行/寻路用自己的一维数组，快且好存 |
| 寻路 | NavMesh / 网格 A* | **网格 A*** | 格子世界最直接，缓存路径即可 |
| 数据 | ScriptableObject / JSON | **JSON + 强类型 POCO** | 可读、可 diff、可被脚本/AI 直接改、运行时热重载 |
| 存档 | PlayerPrefs / JSON 文件 | **JSON 文件** | 明文可查、可版本迁移；路径 Application.persistentDataPath |
| UI | UGUI / UI Toolkit | **UGUI** | 传奇 UI 是重度 Sprite + 拖拽，UGUI 最省事 |
| 输入 | 旧 Input / 新 Input System | **Input System**（简单 Action Map 起步） | 一套代码同时支持键鼠与后续手柄/重映射 |
| 程序集 | 单 Assembly-CSharp / asmdef | **asmdef 分层** | 强制「逻辑层不准 using UnityEngine」，保住可测试性 |

> ⚠️ 本机目前**没有安装 Unity**（/Applications 下无 Unity Hub / Editor）。M0 第一步就是装 Unity Hub + 6.3 LTS。

### 3.2 关键抽象（接口草案）

```csharp
// Domain 层，零 UnityEngine 依赖
public sealed class World {
    public GameMap Map;
    public readonly Dictionary<ActorId, Entity> Entities = new();
    public long Tick;
    public IEventBus Events;
    public IRng Rng;
    public void Step(long tick, IReadOnlyList<Intent> intents) { /* 依次跑各 System */ }
}

public readonly struct ActorId { public readonly int Value; }

public sealed class Entity {
    public ActorId Id;
    public EntityKind Kind;        // Player / Monster / Npc / GroundItem
    public TilePos Pos;            // 逻辑格坐标（唯一权威位置）
    public Dir Facing;             // 8 向
    public Stats Stats;            // HP/MP/MaxHP/MaxMP/DC/MC/SC/AC/MAC/Speed/AtkSpeed
    public int Level, Exp;
    public CombatState Combat;     // 攻击冷却、硬直剩余 tick、目标
    public AiState? Ai;            // 怪物才有
    public Inventory? Bag;
    public Equipment? Gear;
    public SkillBook? Skills;
    public Intent? Pending;        // 本 tick 待执行动作
}

public interface ISystem { void Tick(World w); }

// 逻辑 -> 表现 的唯一通道
public interface IEventBus {
    void Publish<T>(in T evt) where T : struct;
    void Subscribe<T>(Action<T> h) where T : struct;
}
// 事件示例: EntityMoved, DamageDealt, EntityDied, LootDropped, ItemPicked, LevelUp, SkillCast, BuffChanged
```

**要点：逻辑层不知道 GameObject、动画、UI 的存在。** UI、音效、特效、飘字全部只订阅事件。这样：

- 存档 = 序列化 World（几乎白送）
- 单测 = 无头跑 World（快）
- 以后要加服务端 = Domain 直接搬过去
- 表现层换皮不影响逻辑

### 3.3 一次 tick 的执行顺序（固定 100ms）

1. **采样意图** — 输入层把按键翻译成 Intent（移动/攻击/施法/用药/交互），每 tick 最多 1 个主动作。
2. **合法性校验** — 冷却、距离、MP、负重、是否被硬直 → 写入 Entity.Pending。
3. **移动系统** — 每实体每 tick 最多移动 1 格；目标格必须可走且未被占用。
4. **AI 系统** — 状态机 Idle→Patrol→Chase→Attack→Flee→Return；每 N tick（如 5）重算一次 A* 路径。
5. **战斗结算** — 近战按面向与距离判定；法术投射物按 tick 推进；结算命中/闪避/暴击/伤害。
6. **状态与回复** — Buff/DOT 计时，HP/MP 自然回复（按 tick 计）。
7. **死亡与收益** — 死亡标记、掉落表 roll、经验结算、升级、刷新计时。
8. **表现插值**（在 Unity Update 里做，不在 tick 里）— 把实体的视觉位置从「上一格」Lerp 到「当前格」，按 -y 设 sortingOrder。

### 3.4 数值公式（可调，全部进 balance.json）

```
物理伤害 = max(1, RandInt(MinDC, MaxDC) - RandInt(0, Target.AC))
法术伤害 = max(1, RandInt(MinMC, MaxMC) * skill.Coeff - RandInt(0, Target.MAC))
命中判定 = Rand01() < clamp(0.75 + 0.03*(AtkLv - DefLv), 0.30, 1.00)
暴击      = Rand01() < AtkCrit，伤害 x1.5
升级经验  = round(BaseExp * pow(Level, ExpCurve))    // 也可直接做成表格
自然回复  = MaxHP * RegenPctPerTick（非战斗状态才回复）
```

> 传奇的「手感」本质是一堆 tick 数：移速、攻速、硬直帧、技能前摇后摇。**这些全部做成配置项 + 一个运行时调试面板**（能在游戏里直接拖滑条改），不要写死在代码里。

## 4. 玩法系统拆解（按优先级）

图例：**P0 = MVP 必须有**，P1 = 完整版，P2 = 可选/砍掉。

### 4.1 角色与属性 — P0

- 属性：等级 / 经验 / HP / MP / MinDC / MaxDC / MC / SC / AC / MAC / 攻速 / 移速 / 暴击 / 命中。
- 成长：升级自动加属性，不给玩家分点（省 UI 省平衡）。
- ~~负重：CurWeight / MaxWeight，超重不能拾取、移速减半。~~ **已移除**：试玩时上限设得离新手包太近，导致第一件掉落物就捡不起来，体验不好；改成只受格子限制。

### 4.2 三职业 — P0(战士) / P1(法道)

| 职业 | 定位 | MVP 技能 | 完整技能池 |
| --- | --- | --- | --- |
| 战士 | 高 HP 高 DC 近战 | 基本剑术、攻杀剑术 | 烈火剑法、刺杀剑术、野蛮冲撞 |
| 法师 | 脆皮 高 MC 远程 | 火球术 | 雷电术、火墙、冰咆哮、魔法盾 |
| 道士 | 辅助 SC 召唤 | 治愈术 | 施毒术、召唤骷髅、隐身术、灵魂火符 |

> **建议先只做战士**（近战不需要投射物/召唤/AOE，能砍掉一大块代码），跑通完整循环后再补法师、道士。

### 4.3 地图与世界 — P0

- 地图规格：矩形 tile 网格，建议 **100×100 ~ 200×200**，tile 32px。
- 地图三类：**安全区城镇**（无怪、有 NPC、有传送）/ **野外**（散怪）/ **洞窟**（密集怪、掉落好）。
- 障碍：不可走格 + 阻挡物；**一格最多一个实体**（简化占位与寻路）。
- 相机：跟随玩家、限制在地图边界内、支持缩放。
- 深度：sortingOrder = -round(worldY * 100)。
- 传送：地图边缘走出去 / 踩传送点 / NPC 传送，统一由 portals 表描述。

### 4.4 战斗 — P0

- 近战：面向格 + 1 格距离判定，播放挥砍动作与音效。
- 远程/法术 — P1：投射物实体按 tick 移动，碰撞即结算。
- 受击：飘血数字（传奇标志）+ 短暂硬直 + 击退（可选）。
- 死亡：死亡动画 → 尸体 → 掉落 → 按刷新器计时重生。
- 仇恨：谁打我我打谁 + 距离衰减；脱战一定距离/时间后回归。

### 4.5 怪物 AI — P0

状态机 + 数据表参数：视野半径、攻击距离、移速、攻击间隔、伤害、HP、经验、掉落表 ID、是否主动。

### 4.6 物品 / 背包 / 装备 — P0

- 物品类型：消耗品（药水）、装备、材料、技能书、任务物。
- 装备部位：MVP **8 格**（武器/衣服/头盔/项链/手镯/戒指/腰带/靴子），完整版扩到 12~13 格。
- 背包：**6×8 = 48 格** + 堆叠规则。（重量上限已移除）
- 品质：白（普通）/ 蓝（精良）/ 金（稀有）+ 小概率「极品」附加随机词条。
- 掉落：DropTable = (ItemId, 概率, 数量区间, 权重)，金币单独字段。

### 4.7 NPC 与商店 — P0

- 功能 NPC：商人（买/卖）、仓库、技能书商人、传送员。
- 对话：JSON 描述的简单对话树，支持条件与动作（开商店/传送/给物品）。

### 4.8 技能系统 — P1

- 技能数据：MP 消耗、冷却 tick、射程、伤害系数、目标类型（自身/单体/方向/地面 AOE）、特效 ID、音效 ID。
- 学习：使用技能书（物品）→ 学会；重复使用书页 → 技能升级。
- 快捷栏：1~6 键绑定技能，鼠标右键施放（贴近传奇操作）。

### 4.9 存档 — P0

- 存：角色全部数据 + 背包 + 装备 + 技能 + 位置 + 金币 + 已完成的一次性事件。
- 不存：怪物状态与地面掉落（重进按配置重新刷）。
- 文件：persistentDataPath/saves/slot1.json，带 SaveVersion + 迁移函数。

### 4.10 UI / HUD — P0

- HUD：头像+等级、HP/MP 条、经验条、快捷栏、金币、负重。
- 面板：背包(B) / 角色(C) / 技能(K) / 商店 / 对话框 / 系统菜单(Esc)。
- 全局：伤害飘字、拾取提示、升级特效。

## 6. 美术与资源方案（最大的实际风险）

### 6.1 统一规格（先定死，后面才不用返工）

- Tile：**32×32**，PPU = 32，Filter Mode = Point（像素风），相机正交。
- 角色/怪物：4 向（上下左右）或 8 向，每向 **4~8 帧**；单帧 32×48 ~ 48×64（人要高一点）。
- 命名规范：kind_id_action_dir_frame，如 mon_wolf_walk_down_2.png。
- Sprite Atlas 打包，避免 draw call 爆炸。

### 6.2 三阶段美术策略

1. **M0~M3：程序化占位**。写个 Editor 工具一键生成纯色方块/圆 + 朝向标记 + 文字缩写，输出到 Art/Generated/。
   - 优点：零等待，逻辑先行；换图只要改 spriteId 映射。
2. **M4 起：换免费素材**。Kenney（Top-down / Tiny Dungeon）、OpenGameArt 的 LPC 系列、itch.io 免费包，注意逐个确认 License。
3. **可选：外包/AI 生成**贴图，但保持规格不变。

### 6.3 版权红线

- 不使用原版 .wil/.wix 素材、地图文件、原名（比奇省/盟重省/沙巴克等）、LOGO、BGM。
- 不与原版混淆发布；个人本地学习用途。

**M2 逼出来的两个真 bug（都是测试抓的，肉眼看代码很难发现）**：

1. **遍历实体时改集合** —— `DeathSystem` 在遍历 `world.Entities` 的过程中 `Spawn` 掉落物，直接抛
   `InvalidOperationException: Collection was modified`。加了 `World.SnapshotEntities()`，
   「要边遍历边增删就用快照」变成一条明确规则。
2. **尸体在地上滑** —— 怪死了之后 `WantsMove` 还留着上一次 AI 的决策，`MovementSystem` 又没检查存活，
   于是尸体继续走。三处一起修（AI 跳过死亡实体、移动系统跳过、死亡时清意图）。

> 这两个都证明了一件事：**逻辑层能无头跑测试，是这套架构最值钱的地方**。
> 真 Unity 只用来验证"能编译 + 数据能读 + 场景能建"，玩法正确性靠无头用例守住（现在 153 项）。

**M3 逼出来的第三个真 bug（同样是测试抓的）**：

**背包和装备共享了同一个 `ItemInstance` 对象。** `Inventory.RemoveAt` 会把那个对象的 `Count` 减到 0，
而这个对象紧接着被塞进了装备栏 —— 于是「身上的装备」数量变成 0，
后果是换装、卸下全部失败，换下来的旧装备还会因为 `Add(x, 0)` 凭空消失。
修法是跨容器转移一律 `Clone()`。这种 bug 在编辑器里点两下就能触发，但盯着代码看几乎不可能发现。

过程中被真实工具链抓到的三个问题，都不是肉眼看出来的：

1. **`UnityEngine.EntityId` 二义性（CS0104）** —— Unity 6 自带 `EntityId`，视图层同时 `using UnityEngine` 和 `using SimplyCQ.Domain` 就编译不过。
   已把 Domain 的类型改名为 **`ActorId`**，彻底消除这类隐患（桩编译抓不到，因为桩里没有这个类型 —— 这正是必须用真 Unity 编译一次的理由）。
2. **`.tools` 目录名被 Unity 拒绝** —— Unity 不接受工程根目录下的 `.tools`，已改名 `LocalTools`。
3. **模板默认 `activeInputHandler: 1`（只开新输入）** —— 会让键盘完全没反应，已改成 `2`（Both），并在冒烟自检里加了编译期断言。
